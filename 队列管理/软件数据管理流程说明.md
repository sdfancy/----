# 软件数据管理流程说明

## 1. 软件概述

### 1.1 软件功能
本软件作为 **TCP 数据处理中心**，负责协调 PLC、相机、机械臂之间的数据流转，实现工件的入队和出队管理。

### 1.2 软件角色
软件作为 TCP 服务器（数据处理中心），负责协调 PLC、相机、机械臂之间的数据流转。

### 1.3 外部设备
- **PLC**：作为 TCP 客户端，出入队使用两个独立连接
- **相机**：作为 TCP 客户端，可连接 2D 和/或 3D 相机
- **机械臂1 / 机械臂2**：作为 TCP 客户端，向软件请求数据

### 1.4 通信方式
所有设备与软件之间通过 TCP 长连接通信。

### 1.4 端口说明

| 端口 | 用途 | 方向 |
|------|------|------|
| 9999 | PLC 入队连接 | PLC ↔ 软件：入队命令 + 阶段反馈(1Done/2Done) |
| 9090 | PLC 出队连接 | PLC ↔ 软件：出队指针 + 机械臂反馈(1N/1D/2N/2D) |
| 9001 | 2D 相机连接 | 相机 → 软件 |
| 9002 | 3D 相机连接（可选） | 相机 → 软件 |
| 4000 | 机械臂1连接 | 机械臂 → 软件 |
| 4001 | 机械臂2连接 | 机械臂 → 软件 |

## 2. 入队流程

软件支持两种入队流程模式，通过配置 `enqueue_flow_mode` 切换：

### 2.1 旧流程（legacy_single_camera）- 单相机

入队流程由 PLC 发起，分为 5 个步骤：

| 步骤 | 发送方 | 命令 / 数据 | 接收方 | 软件动作 |
|------|--------|-------------|--------|---------|
| 1 | PLC | 01 + count + 入队指针 | 软件 | PLC命令截取转发给相机 |
| 2 | 相机 | 拍照数据 | 软件 | 存入对应队列，发送 1Done 给 PLC |
| 3 | PLC | 11 + count + 入队指针 | 软件 | PLC命令截取转发给相机 |
| 4 | 相机 | 拍照数据 | 软件 | 存入另一队列，发送 2Done 给 PLC |
| 5 | PLC | 12 + count + 入队指针 | 软件 | PLC命令截取转发给相机，入队流程完成 |

**关键规则**：
- 一次入队流程中，PLC 发送的三条命令（01、11、12）中的 count 和入队指针**完全相同**
- 软件收到 01 后建立入队流程上下文，通过 count 和指针控制后续步骤

### 2.2 新流程（dual_camera_11_12）- 2D + 3D 双相机

****这部分是2D+3D的入队流程，中原动力后面不知道还用不用他们的相机，可以先保留这个流程

此流程需要 2D 相机和 3D 相机配合工作：

| 步骤 | 发送方 | 命令 / 数据 | 接收方 | 软件动作 |
|------|--------|-------------|--------|---------|
| 1 | PLC | 11 + count + 入队指针 | 软件 | 创建队列项，给 3D 发 "11,count" |
| 2 | 2D相机 | READY 信号 | 软件 | 记录 READY，请求 2D 数据 |
| 3 | 2D相机 | 类型数据 (type1,type2) | 软件 | 存储类型，等待 12 命令 |
| 4 | PLC | 12 + count + 入队指针 | 软件 | 给 3D 发 "12,count,type1,type2" |
| 5 | 3D相机 | 点位数据 | 软件 | 按标志位分流到 arm1/arm2 队列 |
| 6 | 软件 | Done | PLC | 入队流程完成 |

## 3. 出队流程

### 3.1 机械臂出队

| 步骤 | 发送方 | 数据 / 动作 | 接收方 | 说明 |
|------|--------|-------------|--------|------|
| 1 | PLC | 出队指针（4字节：arm1指针 + arm2指针） | 软件 | — |
| 2 | 软件 | 根据指针从队列取数据，放入缓存区 | — | 等待机械臂取用 |
| 3 | 机械臂 | tada 请求 | 软件 | — |
| 4 | 软件 | 缓存数据 + 反馈码 1N/2N | 机械臂/PLC | — |
| 5 | 机械臂 | 1 或 1,count（完成确认） | 软件 | — |
| 6 | 软件 | 反馈码 1D/2D | PLC | 完成一次出队 |

### 3.2 指针变化检测

- 软件每次收到 PLC 的出队命令后，将本次出队指针与上次记录值比对
- **仅当指针发生变化时**，才执行出队操作（从队列取出新数据填充到缓存区）

### 3.3 预取机制

****这部分，因为新松机械臂那边节拍问题，所以需要预取一拍机制；
****另外，万一后面出现队列数据和工件对不上也可通过这个逻辑来修正

通过配置 `prefetch_offset` 可以实现预取功能：

| prefetch_offset | 行为 |
|-----------------|------|
| 0 | 直接使用目标指针的数据 |
| 1 | 使用目标指针+1 的数据（预取1拍） |

**首件暖机**：`prefetch_drop_first=True` 时，首次预取不足允许返回空数据，避免"总是执行上一件数据"。

### 3.4 缓存区管理

- **每个机械臂独立缓存区**：arm_caches[arm_id]
- **缓存区不清空**：发送后保留，支持机械臂重复请求同一数据
- **重复请求处理**：机械臂每次发送 data 请求，直接返回当前缓存区数据

## 4. 超时处理策略

****这部分是用来处理队列出入队的异常情况，当入队时没有数据可入，或者机械臂要数据时缓存区没有数据，发送一个规定好的默认值

### 4.1 入队超时

**触发时机**：收到新01命令时，检查是否有未完成的等待状态

**处理逻辑**：
1. 检查上轮是否还在等待相机数据
2. 如果是，填充arm1和arm2默认数据（不发1Done/2Done）
3. 清除等待状态，开始新流程

### 4.2 出队超时

**触发时机**：机械臂请求数据时，缓存区无数据

**处理逻辑**：
1. 出队时检查队列项是否有相机数据
2. 如果没有，填充默认值 `(1000,0)E` / `(2000,0)E`
3. 发送握手码让 PLC 继续

## 5. 数据格式

### 5.1 PLC 入队命令格式

```
┌─────────┬─────────┬─────────┐
│ command │  count  │ pointer │
│  2字节  │  2字节  │  2字节  │
└─────────┴─────────┴─────────┘
```

- **command**：命令码（大端序，二进制字节）
  - `0x01`：01 - 开始入队
  - `0x0B`：11 - 触发相机（PLC发送0x0B，解析为11）
  - `0x0C`：12 - 入队完成（PLC发送0x0C，解析为12）
- **count**：计数值（2字节，大端序）
- **pointer**：脉冲指针（2字节，大端序）

**示例**：
- `00 01 00 C8 00 64` → command=1, count=200, pointer=100
- `00 0B 00 C8 00 64` → command=11, count=200, pointer=100
- `00 0C 00 C8 00 64` → command=11, count=200, pointer=100


### 5.2 队列存储格式（完整数据）

```
(标志位,count,点位数据)E
```

- `( )` ：左右括号（英文符号）
- 标志位 ：相机识别的工件类型，标志位的第一个数字（1XXX=arm1, 2XXX=arm2），代表是哪个机械臂的数据
- count ：PLC 发送的计数值，用于管理队列，保证数据唯一且连续
- 点位数据 ：机械臂工作所需的数据（多个字段以逗号分隔）
- E ：大写字母 E，机械臂的接收结束符

**示例**：`(1001,123,100,200,50)E`
          `(2001,123,100,200,50)E`


### 5.3 2D+3D（双相机模式）数据格式

- **2D 相机**：返回类型数据 (type1,type2)
- **3D 相机**：返回点位数据，软件根据标志位千位分流到对应队列

### 5.4 发送给3D（双相机模式）的触发命令

```
┌─────────┬─────────┐
│ command │  count  │
│  2字节  │  2字节  │
└─────────┴─────────┘
```

软件转发给相机的触发命令为 **4字节**（不含 pointer）。

**命令示例**：
- `00 01 00 C8` → command=1 (0x01), count=200
- `00 0B 00 C8` → command=11 (0x0B), count=200
- `00 0C 00 C8` → command=12 (0x0C), count=200



### 5.5 默认填充数据

默认填充数据场景：

| 场景 | 格式 | 说明 |
|------|------|------|
| 入队超时（新01收到时上轮未完成） | `(1000,count)E` / `(2000,count)E` | count 为该工件的实际计数值 |
| 机械臂要数据时无缓存 | `(1000,0)E` / `(2000,0)E` | **count=0 表示这是默认值** |

可通过配置 `default_payloads` 修改默认值格式。

## 6. 现场竞态问题与解决方案

****已解决，通过PLC编程，软件按照流程设计即可，不需要考虑这方面内容

### 6.1 问题现象

机械臂偶发收不到数据，推测由竞态引起。

### 6.2 原因分析（已通过 PLC 延时解决）

- **原问题**：PLC 发送 IO 信号给机械臂（触发机械臂发送 data）的**同时**，也会发送出队指针给软件
- **当前方案**：PLC 侧已增加 **800ms 延时**，先发送出队指针，800ms 后再发送 IO 信号
- **效果**：从根本上消除了竞态条件，机械臂的 data 请求总是在出队指针之后到达

### 6.3 软件端竞态处理（防御性编程）

**处理顺序：先发送缓存区数据 → 再执行出队并更新缓存区**

具体逻辑：

1. 软件收到机械臂的 data 请求 → **立即将当前缓存区数据发给机械臂**（不检查指针变化，不清空缓存区）
2. 随后检查 PLC 最近一次给出的出队指针是否发生变化：
   - **若发生变化**：执行出队操作，从队列取出新数据，覆盖写入缓存区
   - **若无变化**：保持缓存区不变

**现状说明**：
- 由于 PLC 已增加 800ms 延时，竞态条件已基本消除
- 此代码作为**防御性编程**，处理极端情况下的边界保护（如网络延迟波动、PLC 延时不稳定等）

**对正常流程的影响**：
- 如果没有发生竞态（PLC 出队指针先到，机械臂后请求数据），软件正常返回缓存数据
- 如果发生竞态（机械臂先请求数据，PLC 出队指针后到），软件先返回旧缓存，再更新为新缓存
- 无论哪种情况，对机械臂的响应都不会失败，只是数据可能是"旧数据"还是"新数据"的区别

## 9. 补充说明

- 所有网络通信均基于 TCP 协议，软件作为服务器端监听，各设备作为客户端主动连接
- 软件需维护多个客户端会话，根据命令内容或连接对象区分来源与目标设备
- 入队指针和出队指针由 PLC 统一管理，软件只负责按指针操作队列
- 设备断线时，软件保持监听，持续接受客户端的新连接

### PLC 连接说明

PLC 与软件之间建立**两个独立的 TCP 连接**：

- **入队连接（9999）**：PLC 发送 01/11/12 入队命令，软件发送 1Done/2Done 阶段反馈
- **出队连接（9090）**：PLC 发送出队指针，软件发送 1N/1D/2N/2D 机械臂反馈

## 10. 配置参数说明

### 10.1 队列运行策略配置（QUEUE_RUNTIME_CONFIG）

位置：`config/settings.py` 中的 `QUEUE_RUNTIME_CONFIG`

| 参数 | 可选值 | 说明 | 适用场景 |
|------|--------|------|---------|
| `enqueue_flow_mode` | `legacy_single_camera` | 旧流程：单相机，PLC 发送 01→相机→11→相机→12 | 单相机模式 |
| | `dual_camera_11_12` | 新流程：11/12 + 2D/3D 双相机配合 | 双相机模式 |
| `unknown_enqueue_policy` | `ignore` | 忽略非 01/11/12 的入队命令（默认） | 防止误触发 |
| | `legacy` | 回退到旧 queue_manager 处理 | 兼容旧协议 |
| `prefetch_offset` | 0 / 1 | 预取偏移：0=用目标指针数据，1=用目标+1数据 | |
| `prefetch_drop_first` | `True` / `False` | 首件暖机：预取不足时是否允许空数据 | |
| `drop_late_camera_data` | `True` / `False` | 是否丢弃晚到的相机数据（已超时或已出队后到达） | |
| `completion_count_validation` | `True` / `False` | 机械臂回包1,count时启用计数校验 | |
| `send_default_on_empty_request` | `True` / `False` | 机械臂请求数据时，如果缓存为空是否发送默认值 | |

### 10.2 日志配置（LOGGING_CONFIG）

位置：`config/settings.py` 中的 `LOGGING_CONFIG`

| 参数 | 说明 | 示例值 |
|------|------|-------|
| `log_level` | 日志级别 | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `log_mode` | 日志模式 | `simple`=单文件 / `detailed`=多文件（记录原始通讯） |
| `log_file` | 日志文件路径（仅 simple 模式使用） | `logs/system.log` |
| `enqueue_log_file` | 入队日志文件路径（仅 detailed 模式） | `logs/enqueue.log` |
| `dequeue_log_file` | 出队日志文件路径（仅 detailed 模式） | `logs/dequeue.log` |
| `max_file_size` | 单个日志文件最大大小 | 500MB（约记录 40-50 天数据） |
| `backup_count` | 备份文件数量 | 5（约保留 200-250 天） |
| `history_limit` | 内存中历史记录条数（用于 HMI 显示） | 1000 条 |
| `timestamp_ms` | 是否显示毫秒 | `True` / `False` |

**日志模式区别**：
- **simple 模式**：仅使用 `system.log`，不记录原始通讯内容
- **detailed 模式**：使用 3 个日志文件（enqueue.log / dequeue.log / system.log），记录原始通讯内容
