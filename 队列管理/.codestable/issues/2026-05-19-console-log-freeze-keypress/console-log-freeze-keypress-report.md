# 终端日志按键后才刷新 Issue Report

## 1. 问题现象

运行主程序后，终端窗口中的日志输出会卡在某个位置。测试时发现，需要一直长按键盘按键，例如 Delete 删除键，终端窗口才会刷新，程序才会正常与其他设备通讯并收发数据。不按键盘按键时，日志输出停在原位置；等按下键盘按键后，之前已经产生的日志会一次性全部刷新出来。

## 2. 复现步骤

1. 启动主程序。
2. 让程序与 PLC、相机、机械臂等外部设备进行通讯测试。
3. 不操作键盘，观察终端窗口日志输出。
4. 长按键盘按键，例如 Delete。
5. 观察到：终端窗口刷新，之前积压的日志集中输出，设备通讯和数据收发恢复正常表现。

复现频率：用户反馈测试中可复现，具体频率待确认。

## 3. 期望 vs 实际

**期望行为**：程序启动后，即使不按键盘，终端日志也应持续刷新，外部设备通讯和数据收发应持续正常进行。

**实际行为**：不按键盘时，终端日志停住，设备通讯和收发数据表现为卡住；按住键盘按键后，终端刷新并集中输出之前积压的日志，通讯恢复正常表现。

## 4. 环境信息

- 涉及模块 / 功能：主程序运行时终端日志输出、设备通讯主流程。
- 相关文件 / 函数：待定；已知启动入口为 `src/main.py`，日志系统为 `src/utils/logger.py`。
- 运行环境：Windows 本地终端环境，具体终端类型待确认。
- 其他上下文：问题出现在运行程序后的终端窗口中；按键操作会影响日志刷新和设备通讯表现。

## 5. 严重程度

**P1** — 核心设备通讯受影响，但目前存在长按键盘按键的人工绕过方式；需要尽快定位并修复。
