# 让现场设备按同一个工件节拍交接数据

## 用户故事

- 作为现场调试人员，我希望一个工件进入产线后，两台机械臂拿到的都是同一个工件对应的数据，而不是各自队列错开一拍。
- 作为设备维护人员，我希望相机短暂超时或机械臂重复要数据时，流程还能继续跑，而不是因为一次缺数据让整条线停住。
- 作为 PLC 联调人员，我希望软件按 PLC 给出的入队和出队节拍推进，而不是自己生成另一套节拍造成脉冲和数据对不上。
- 作为操作人员，我希望能看到队列、缓存和设备状态，方便判断当前卡在入队、出队还是设备连接。

## 为什么需要

这套系统同时连接 PLC、相机和两台机械臂，真正难点不是单次收发数据，而是让"工件、脉冲、相机结果、机械臂取数"始终对得上。现场任何一个环节慢一点、断一下、重复发一次请求，都可能让后续工件拿到上一件或下一件的数据。没有统一队列基线，问题会表现成偶发错位，排查成本很高。

## 怎么解决

软件以 PLC 节拍作为主线，为每个工件维护两台机械臂各自要用的数据，并在入队、相机回包、出队、机械臂取数、完成反馈之间保持同一个工件上下文。相机数据没及时回来时，系统用约定的默认数据补位；机械臂重复请求时，继续返回当前缓存；设备短暂离线时，软件等待恢复后继续按 PLC 指针推进，避免队列和现场脉冲分家。

## 边界

- 它不负责决定 PLC 的脉冲算法，也不替 PLC 管理现场节拍；PLC 仍是入队和出队指针的来源。
- 它不保证相机一定能识别成功，只保证相机缺数据时流程有默认兜底，不让队列错位。
- 它不负责机械臂动作规划，只负责在机械臂请求时给出当前工件对应的数据并反馈完成状态。
- 它不把 HMI 当作业务队列；界面只用于查看状态和辅助联调。
- 双相机和预取这类策略属于同一能力下的运行模式，开启前需要现场确认设备流程和节拍已经匹配。
